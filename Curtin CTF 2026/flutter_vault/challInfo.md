## Challenge

Version 2 of the vault, rewritten in Flutter for security. jadx shows almost nothing this time. Where did the logic go?

## Approach

### Phase 1 — Analyze

1. Extracted the APK and found `classes.dex` (almost empty — just Flutter bootstrap) and `lib/arm64-v8a/libapp.so`, which is where Flutter stores its ahead-of-time compiled Dart code.
2. Ran `strings libapp.so` and found `CURTIN_CTF{`, `Vault opened!`, and `Access denied` — confirming the flag validator lives in the native library, not Java.
3. The APK targets Dart **3.13.7** and exports `_kDartSnapshotData` and `_kDartSnapshotText` (unified snapshot symbols, not the older split `_kDartVmSnapshot*` names).

### Phase 2 — Recon and Analysis

4. Used **Blutter** to parse the Dart AOT snapshot. The original checkout expected `_kDartVmSnapshotData` and failed at symbol lookup; Blutter PR #230 patched that. The full analysis also hit the Kali VM's memory limit, so ran the patched version with `--no-analysis` to generate `pp.txt` (the object pool dump).
5. From `pp.txt`, identified two entries:
   - `[pp+0xbef8]` → the string `CURTIN_CTF{` (prefix)
   - `[pp+0xbf00]` → a **22-element integer list** (the target comparison table)
6. Loaded `libapp.so` in Ghidra / objdump and located the validator at `0x1ec490`. Traced the disassembly:
   - `0x1ec4c4`: loads the prefix
   - `0x1ec768`: loads the 22-element table
7. Identified a three-step transform applied to the user's 22-character input before comparison:
   - **Step 1 — XOR with a generated byte stream.** LCG starting at `state = 0x1337`, advancing as `state = (state * 1103515245 + 12345) & 0x7fffffff`; XOR byte = `(state >> 16) & 0xff`.
   - **Step 2 — Rolling mix with previous result.** `mixed[0] = xored[0]`; for `i > 0`: `mixed[i] = (xored[i] + 3 * mixed[i-1]) & 0xff`.
   - **Step 3 — Permuted comparison.** The validator checks `table[i] == mixed[(5*i) % 22]` for all i.

### Phase 3 — Infiltrate

8. Inverted the transform offline in Python:
   - Undo permutation: for each `i`, `mixed[(5*i) % 22] = table[i]`.
   - Undo the rolling mix: `xored[i] = (mixed[i] - 3 * mixed[i-1]) & 0xff` (with `mixed[-1] = 0`).
   - Undo the XOR: regenerate the same LCG stream and XOR back.

```python
table = [
    0x59, 0xfb, 0xc2, 0xb2, 0xb7, 0xdf, 0x6c, 0x90,
    0x13, 0x39, 0x2a, 0xa1, 0xdb, 0x0a, 0x66, 0xe2,
    0xe9, 0x76, 0x28, 0xaa, 0x22, 0x52,
]

mixed = [0] * len(table)
for i, value in enumerate(table):
    mixed[(5 * i) % len(table)] = value

state = 0x1337
previous = 0
body = bytearray()

for value in mixed:
    state = (state * 1103515245 + 12345) & 0x7fffffff
    unmixed = (value - 3 * previous) & 0xff
    body.append(unmixed ^ ((state >> 16) & 0xff))
    previous = value

print("CURTIN_CTF{" + body.decode("ascii") + "}")
```

9. Script output: `CURTIN_CTF{redacted}` — derived entirely from the disassembly and object pool, no dynamic execution needed.

## Tools

- `apktool` / `unzip` — APK extraction
- `strings` — initial triage of `libapp.so`
- **Blutter** (with PR #230 patch, `--no-analysis` flag) — Dart AOT snapshot parser → `pp.txt`
- **Ghidra** / `objdump` — ARM64 disassembly of the validator
- Python 3 — offline flag recovery script

## Lessons

- Flutter AOT apps store all logic in `lib/<abi>/libapp.so`; `jadx` and `dex2jar` are dead ends — go straight to the `.so`.
- Dart 3.13+ uses unified snapshot symbols (`_kDartSnapshotData`/`_kDartSnapshotText`); older Blutter builds expect the split names and fail — patch or use a fork that handles both.
- When Blutter's full analysis OOMs, `--no-analysis` still produces `pp.txt` with the object pool, which is often enough to locate string constants and integer tables without a full decompilation.
- The permutation `(5*i) % 22` is invertible because `gcd(5, 22) = 1`; always check coprimality before assuming a permutation is a 1-to-1 mapping.
