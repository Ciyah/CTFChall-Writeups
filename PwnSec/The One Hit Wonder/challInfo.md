# The One Hit Wonder

## Challenge
https://youtu.be/jNQXAC9IVRw



- @ibrahim 

## Approach
1. Option 1 discloses the 1536-bit prime `p`, and option 2 permits eight chosen
   inputs.  Querying the exact values `x = 0, 1, 2, 3, 4, 5, 6, 7` produces
   the top 890 bits of

   `z_i = v * (u + i)^(-1) mod p`.

2. The flaw is the reuse of the same hidden `u` and `v` while revealing 58% of
   eight modular inverses.  This is the Modular Inversion Double Hidden Numbers
   Problem (MIDHNP).  Write each exact value as `z_i = (y_i << 646) + e_i`,
   where `0 <= e_i < 2^646`.  Determinants of the equations

   `(u + i) * z_i - v = 0 mod p`

   eliminate `u` and `v`.  The determinant construction yields multilinear
   polynomials in the small errors which vanish modulo powers of `p`.

3. `determinant_attack.py` implements the determinant-based MIDHNP construction.
   With `d = 2`, all square-free monomials of degree at most three give a
   93-dimensional lattice.  LLL produced 49 sufficiently short vectors, hence
   49 cubic polynomials which vanish over the integers at the error vector.
   Overdetermined floating-point least squares finds a basin, and arbitrary-
   precision Newton iteration recovers all 646 bits of each `e_i` exactly.

4. Recover the secrets from the first two complete outputs:

   `u = (z_1 * 1 - z_0 * 0) * (z_0 - z_1)^(-1) mod p`

   `v = z_0 * u mod p`

   The solver verifies all eight oracle equations, selects menu option 4, and
   submits `u` and `v` in the same connection.

Exact command:

```sh
python3 -u solve.py
```

The recovered `u` and `v` are randomized on every connection, so the exact
numeric submissions are generated by the solver for that live session.

## Tools

- Python 3 standard library for the TLS client
- `fpylll` for LLL
- SciPy and mpmath for high-precision root recovery

## Lessons

- Reusing the denominator offset and numerator turns truncated modular inverses
  into MIDHNP samples.
- A determinant eliminates both large secrets while preserving small error
  variables.
- Exact verification should precede the final submission because approximate
  CVP solutions can closely imitate the leaked prefixes.
